# 项目开发知识

知识入口：`/knowledge/INDEX.md`。

1. 读取当前工作区的 Git remote、分支和 HEAD；在入口中匹配仓库身份。项目目录改名不代表项目改变，同名目录也不证明是同一仓库。
2. 读取入口同目录的 `catalog.json`，只使用该项目 `documents` 中列出的当前文件；目录里保留的其他 Markdown 可能是过期结果。代码状态为 `ready` 时读取 `CODEBASE.md`，需要具体模块再读已列出的 `MODULES.md` 有关章节；不要一次读取全部仓库或全部归纳。
3. 用资料定位本次任务的入口、调用关系、已有实现和测试，再打开当前工作区对应源码。知识文件绑定的提交与工作区不同时，先核对相关差异，不能直接沿用旧行为结论。
4. 结论引用的 GitHub 地址绑定生成时的 commit。静态代码归纳不证明测试通过、服务在线或用户已批准外部操作；文档中的旧状态、候选方案和会话说法按其证据边界使用。
5. 入口标为“待归纳”、文件缺失或项目不匹配时，说明当前知识缺口并直接检查真实源码；不能把其他项目资料套用过来，也不要让用户通过网页问答才能继续开发。

涉及历史决定、重复故障或接续任务时，按需读取 catalog 已列出的 `SESSIONS.md` 和 `SESSION-TOPICS.md`。代码与会话分别完成，不要求代码先完成才能读取已发布的会话知识。经验条目保留用户决定、候选经验、未决问题及源码关联的区别；依据和源码引文匹配不代表当前测试或部署已经通过。未列出时说明归纳尚未完成，再读 `SESSION-INDEX.md` 中相关的 `history/*.md`。

`recorded_git_remote` 是会话记录中的仓库身份；`same_recorded_workspace` 只是无冲突历史目录关联。两者都不证明会话主题属于该项目，例如在项目目录启动的本机迁移会话应排除。主题分类使用用户请求与有限助手摘录；经验提炼使用选定证据及相邻记录，读取范围见 `history-provenance.json`。脱敏原文没有全部通过模型审计，转述的工具结果也不等同于执行证明。

知识文件由 Repomix 整理源码、强模型分批归纳生成。只读使用；原始检出、覆盖范围和生成身份见项目的 `provenance.json` 及入口链接的拉取记录。未经用户要求，不把归纳改写成全局规约，不修改原始会话。
